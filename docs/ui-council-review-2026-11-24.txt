VERITAS UI COUNCIL REVIEW — 24 NOVEMBER 2026

Scope: recommendations and visual research, not an implementation pass.
Audience: teens and adults, with teacher-managed classrooms.

Evidence: inspected the running signed-in Home, Study and AI setup at desktop width, and Study at a 390x844 phone viewport; inspected current React components and final stylesheet cascade. The mobile viewport was restored. No provider request, classroom post, account setting, age declaration or learning completion was submitted for this review.

All ten distinct callable council models completed independent source reviews:
gpt-6.2-astra, gpt-6.2-sol, gpt-6.1-terra, gpt-6.1-sol,
gpt-6-astra, gpt-6-sol, gpt-6-luna, gpt-5.6-sol,

MAIN RECOMMENDATION

Build on the existing stone/cobalt light theme and slate/periwinkle dark theme. Make the product resemble a modern reasoning notebook: clear labeled tools, generous reading space, annotated claims and evidence, restrained semantic accents. Use small explanatory visuals before adding large decorative images. Keep the current single primary Home action.

HIGH PRIORITY — STRUCTURE AND COMPREHENSION

01. Replace repeated navigation initials with distinctive icons AND readable labels.
Observed: AppShell.tsx uses name.charAt(0), causing Practice/Profile, Daily/Debate and Leaderboard/Live collisions. Desktop navigation starts collapsed.
Change: visible desktop labels, meaningful Lucide icons, a small set of primary destinations and grouped secondary activities. Suggested organization: Home; Practice (drills, daily, AI/live); Study; Evidence; Classroom; account menu for Profile/settings; optional competition/Arcade under More. Test grouping with users rather than treating it as settled.

02. Return the phone's width to the content.
Observed: the 390px Study viewport has a 68px permanent rail and about 307px main content width, with the remaining difference used by the scrollbar. The result is a narrow reading column even without horizontal overflow.
Change: compact header with a labeled drawer or a small labeled bottom bar plus More. Keep all destinations reachable, support Escape/focus return, and respect safe areas. Choose one primary mobile navigation pattern; do not render redundant bottom and side navigation.

03. Make Study's next lesson the first useful block.
Observed: the large PDF uploader and weekly goal appear before the recommended lesson, putting that lesson below the first screen on desktop and farther below on phones.
Change: Next lesson / Review due first; Learning paths next. Give Paper Study, Notes and preferences clearly named secondary entry points. Keep paper upload disclosures next to the uploader after moving it.

04. Prioritize real tasks on Home.
Observed: the resume/recommended card is already a useful focal point. The general recommendation precedes a generic Classroom tile, and failed assignment delivery is shown late.
Change: needs-attention delivery notice first, then an actual due assignment when available, then resume or a recommended drill. Use a concrete sample argument and a trustworthy duration estimate. Use Start for fresh practice; Continue only when work is being resumed. Do not invent deadlines, personalized reasons or progress.

05. Give Classroom separate task views for each role.
Source-observed: join/create, assignment editing, submissions, progress, announcements, people, invitations and discussions share one long surface. Populated multi-role flows were not exercised in this review.
Change: students see Due next / In progress / Feedback; teachers see Needs review / Assignments / People / Reports. Each assignment shows status, due date, activity type and next action. Keep rubric and attempts easy to reach. Show the role for the current cohort; an account may teach one class and study in another.

06. Fix the lesson stage highlight before embellishing the stepper.
Confirmed in Study.tsx:125: stages holds capitalized labels while stage contains lowercase values, so stages.indexOf(stage) is -1 and the intended completed styling never applies.
Change: use explicit stable stage IDs, distinguish current/completed/upcoming, and expose the current step to assistive technology. On phones, Step 2 of 5 can be clearer than five cramped labels. Do not make future steps clickable if skipping would break the learning sequence.

07. Unify the visual foundation.
Source-observed: layout.tsx loads styles.css, workspace.css and mockup-ui.css. They contain different font, color, radius and surface rules; the final layer implements Stone/Cobalt and Gill Sans. Earlier layers are not proof of the final rendered style.
Change: a single semantic set of canvas/surface/text/action/caution/error tokens and a consistent button, field, disclosure and card family. Aim for readable 16–18px lesson/quote text, comfortable metadata and roughly 60–75 characters per line where appropriate. Verify actual contrast in both themes rather than assuming current colors fail.

08. Make evidence context one reading unit.
Source-observed: featured quotes, source details, questions, findings, interpretations, limitations and trace are distributed across several sections. Existing featured quotations and Use this quote actions are useful and should stay.
Change: checked proposition -> quotation -> bounded interpretation -> limitation -> source/author/date -> excerpt type. Put assessment coverage and unassessed-source counts near the top. Use labels such as Abstract excerpt or Retrieved web excerpt. Add a source inspector on desktop and inline expansion on mobile. Keep sources readable when AI is unavailable. Never use a truth meter or imply a photograph verifies a finding.

NEXT — VISUAL TEACHING AND FLOW

09. Add an annotated argument preview to Home.
A compact original diagram or index-card illustration can show Claim -> Reason -> Evidence, with a highlighted weak connection. Place it beside the existing CTA on desktop; shrink it or place it after the CTA on phones. It should communicate what learners do, not merely fill empty space.

10. Turn Study's weak/strong examples into visual comparisons.
Highlight a phrase such as proves changing to is associated with, with a brief explanation of why. Keep the actual text selectable, label both versions and stack them in logical order on phones. Add diagrams for claim/support, counterarguments, source independence and scope. Every instructional diagram needs an equivalent explanation.

11. Make argument maps look connected.
The current nested outline is functional. Add clear connecting rules, point-type labels and a focused branch view or optional compact overview. Keep the accessible outline available. Start with CSS/SVG relationships rather than a complex pan/zoom canvas; do not add drag-only editing.

12. Make AI setup predictable before adding more settings.
Keep the existing motion/stance choices and advanced timing disclosure. Add three neutral starter motions and a compact session brief showing side, written/speech mode, opponent behavior, turns and timing. Explain what happens after Begin. Put sign-in/service requirements near the top for guests and label teacher-locked settings. Retain quick one-page setup for returning users.

13. Reframe Profile around practice evidence.
Lead with recent completed activity, skills with sufficient evidence and the next useful practice. Keep XP, rank and live results as a separate optional competition section. Show assessment count and recency adjacent to each estimate; distinguish Unassessed from zero performance. A clear skill list is more interpretable than duplicate radar and percentage bars.

14. Make empty states specific and actionable.
No saved quotes: show a small document motif plus how to save the first one. No classroom: show Join a classroom and the code requirement. No study history: show one starter lesson. No public matching eligibility: show the relevant preferences and teacher-assignment path. Avoid large illustrations that bury the action.

15. Clarify progress and failure states visually.
Use compact status steps with a plain current phase, elapsed/long-running explanation, cancel and retry. Keep preserved work visible and separate search success from assessment success. Do not use a moving progress bar that pretends to know how much work remains.

16. Refine interaction and focus treatment.
The Home capture showed a large focus outline around the entire main region after navigation. Review the visual result while preserving skip links and route focus management. Prefer targeted keyboard-visible focus and a clear heading/active-route cue. Check loading/disabled controls and error placement. Do not simply remove focus indicators.

17. Make text hierarchy calmer.
Reduce repeated uppercase eyebrow labels and arrow decoration. Use one clear page title, a short purpose statement and a dominant action. Differentiate controls, quotations, metadata and caution text by typography and spacing. Favor a small number of meaningful surface levels over equally weighted bordered rectangles everywhere.

18. Make classroom tables and long source titles phone-friendly.
Use labeled assignment/submission rows that become cards when narrow. Preserve data labels and essential actions. Let long titles wrap. Avoid hover-only explanations and clipped status chips. Check with realistic long content rather than only empty states.

IMAGE RULES

Use one visual family. Limit decorative imagery to entry/empty states. For topics, choose neutral contextual photos rather than partisan or emotionally loaded images; the same image must not favor one side. Prefer consented or non-identifying imagery for school context. Decorative images should have an empty alt; informative diagrams require meaningful alternatives. Keep important text out of raster images, provide dimensions, optimize raster formats and respect reduced motion. Do not add publication logos, author faces or document thumbnails unless they are authentic and their use is appropriate.

COUNCIL DISAGREEMENTS RESOLVED

- Some models read earlier CSS and inferred that mobile links disappear. The live current mobile rail showed all destinations in a scroll area. Retained finding: it consumes reading width and uses ambiguous initials; missing navigation is not asserted.
- Several models suggested violet/mint or a new paper palette. The final CSS already has Stone/Cobalt and a dark companion theme. Consolidate that existing system before inventing another palette.
- Some favored a multi-step debate wizard; others favored quick setup. Recommendation: keep the one-page quick path and add a compact summary first, then test whether a first-run guided path is needed.
- Some favored balanced support/challenge columns. Show the perspectives actually found and missing coverage; do not force an equal number of sources or imply equal evidential quality.
- Keep competition available, but secondary. Removing it outright could harm users who value live debates.

SUGGESTED DELIVERY ORDER

First: navigation/mobile shell, Study entry order/stage states, shared typography and components.
Second: role-focused Classroom and task-aware Home, evidence reading hierarchy.
Third: original instructional diagrams, one Home spot illustration, setup brief and progress presentation.
Then: contextual public-page photography and optional source previews only where they add value.

Validate with concrete tasks: locate an assignment, find the next lesson, resume a run, explain a source's limitation, save/use a quote and identify the next debate action. Check desktop and phone, keyboard and screen reader, long content, no-image mode, both themes, 200% text zoom and 320px reflow. The expected gains are design hypotheses until tested with learners and teachers.

APPROVED COLOR / TYPE ITERATION — DESKTOP PRIORITY

The user approved larger typography and clearer navigation after reviewing Chess.com, Lichess, Duolingo and Khan Academy, then chose an independent, livelier palette that avoids blue. During implementation they asked to prioritize desktop and stop spending time on phone QA.

Implemented: ivory (#FAF7F0), terracotta (#AD4934), golden learning, leaf evidence and plum debate accents, with a warm charcoal (#272520) dark companion. Shared typography now uses 17px body, 18px lesson reading, 16px controls/main navigation and 14px essential captions at the default browser font size. Removed miniature font overrides and replaced legacy blue CSS literals with shared theme tokens. Desktop headers are shorter, page padding is tighter and Home activity cards have distinct accent surfaces. The reasoning diagram is supporting content beside the main action on wide screens and an optional disclosure in narrower reading spaces.

Navigation is Home / Practice / Learn / Evidence / Debate / Classroom / More. AI and live debate are grouped under Debate; Daily Challenge, Arcade and Leaderboard are in More. Navigation uses real destination links and retains modified-click behavior. Help is persistent; Profile, preferences, theme and sign-out are grouped under the account disclosure. Desktop collapse/expand remains available. Lessons use a separate sticky progress column at wide widths, with a spaced toolbar. Debate opponent options use equal-width columns on desktop.

Verification: 67 tests and TypeScript passed after the functional changes; the final production webpack build passed after desktop styling refinements. Browser review covered 1440px and 1280px desktop layouts, light Home/Learn/Debate/Classroom and the warm dark companion, actual 18px lesson text, Recall-to-Learn state and desktop navigation collapse/expand. No horizontal page overflow was observed at the checked desktop sizes. Calculated foreground/background contrast exceeded 4.5:1 for the selected body, muted, primary-button and activity-label pairs in both themes; this does not certify every UI state. Earlier phone checks were set aside at the user's direction, and the temporary viewport override was reset. No live AI exchange, classroom post, recording or destructive account action was submitted.
